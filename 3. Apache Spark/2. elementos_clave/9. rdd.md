# Resilient Distributed Dataset (RDD)

Es la **estructura de datos base de Spark.**

Antes de DataFrames y Datasets, todo en Spark era RDD.

## Definición técnica

Un RDD es:

- Inmutable

- Distribuido en particiones

- Paralelizable

- Tolerante a fallos (gracias al lineage)

## Ejemplo

Si cargamos un archivo:

``` python

    rdd = spark.sparkContext.textFile("ventas.txt")

```

Internamente:

- El archivo se divide en particiones

- Cada partición se envía a un [executor](3.%20executors.md)

- Cada [executor](3.%20executors.md) procesa su parte

Visualmente:

``` scss

RDD
 ├── Partición 1 (Nodo A)
 ├── Partición 2 (Nodo B)
 ├── Partición 3 (Nodo C)

```

## Por qué “Resilient”

Porque si una partición se pierde:

- Spark usa el [lineage](8.%20lineage.md)

- Recalcula solo esa partición

No necesita replicar todo.

## Transformaciones y acciones

RDD tiene:

**Transformaciones (lazy)**

- map

- filter

- flatMap

- reduceByKey

**Acciones (ejecutan)**

- collect

- count

- saveAsTextFile

Todo funciona igual que con DataFrames, pero más bajo nivel.

## ¿Un DataFrame usa RDD?

Sí.

Un DataFrame es una abstracción de alto nivel que internamente está construido sobre RDDs.

Arquitectura simplificada:

``` markdown

DataFrame API
     ↓
Catalyst Optimizer
     ↓
RDD Execution

```

RDD es el motor base de ejecución.
