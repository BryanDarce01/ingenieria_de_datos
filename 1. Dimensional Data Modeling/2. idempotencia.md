# ¿Qué es idempotency en ingeniería de datos?

**Idempotencia** significa que puedes ejecutar una operación múltiples veces y el resultado final será siempre el mismo, sin efectos secundarios adicionales.

En otras palabras:

- **Una operación idempotente produce el mismo resultado sin importar cuántas veces se repita.**

# 🔧 ¿Por qué es importante en ingeniería de datos?

En pipelines ETL/ELT, APIs, jobs programados y sistemas distribuidos, puede ocurrir que una operación:

- se ejecute dos veces por error,

- falle a la mitad y vuelva a reintentarse,

- sea activada de forma duplicada.

Si una operación no es idempotente, ocurren problemas como:

- datos duplicados,

- inconsistencias,

- corrupción en tablas,

- resultados inesperados cuando un job se reejecuta.

# 📌 Ejemplos prácticos
### ✔️ Ejemplo idempotente

Un proceso que borra y vuelve a cargar una tabla completa (“truncate-load”) es idempotente:

`TRUNCATE TABLE ventas`

`INSERT INTO ventas SELECT …`

No importa si se ejecutas 1, 2 o 10 veces:

**la tabla termina con los mismos datos.**

# ❌ Ejemplo NO idempotente

Agregar registros sin control:

``` sql 
INSERT INTO ventas SELECT * FROM staging_ventas;
```

Si el job se ejecuta dos veces, tendrás datos duplicados → **no idempotente.**

# ✔️ API idempotente

Un `PUT` que actualiza una entidad:

``` bash 
PUT /usuario/123
{ "nombre": "Bryan" }
```

Ejecutarlo 10 veces no genera cambios adicionales → **idempotente**.

# 🛠️ ¿Cómo se logra la idempotencia en data engineering?

Algunas técnicas comunes:

## 🔹 1. `UPSERT (merge)`

Reemplazar o actualizar según llave primaria:

``` sql
MERGE INTO tabla t
USING staging s
ON t.id = s.id
WHEN MATCHED THEN UPDATE ...
WHEN NOT MATCHED THEN INSERT ...
```

## 🔹 2. `INSERT OVERWRITE`

**Borra el contenido existente** (de toda la tabla o de una partición específica)
y luego **inserta el nuevo resultado.**

En otras palabras:

⚡ **Sobrescribe los datos anteriores con los datos nuevos**.

``` sql
INSERT OVERWRITE TABLE ventas
SELECT * FROM staging_ventas;
```

### Resultado:

- La tabla ventas queda vacía.

- Se cargan los datos nuevos.

- No quedan duplicados.

- Si el job se corre dos veces, el resultado es siempre igual → **idempotente.**


## ✔️ Ejemplo de sobrescribir solo una partición

``` sql
INSERT OVERWRITE TABLE ventas PARTITION(fecha='2025-01-01')
SELECT * FROM staging_ventas
WHERE fecha = '2025-01-01';
```
Esto es muy usado en pipelines diarios.

## 🎯 ¿Por qué es tan importante?
- ✔️ 1. **Evita duplicados**

    - No usa `INSERT INTO` (que solo agrega datos).

- ✔️ 2. **Hace el pipeline idempotente**

    - Ejecutarlo varias veces da el mismo resultado.

- ✔️ 3. **Limpia y reemplaza datos de manera segura**

    - Ideal para cargas:

        - diarias

        - mensuales

        - particionadas

- ✔️ 4. **Permite refrescar solo una partición**

    - Carga eficiente para big data

## ❌ ¿Cuándo NO usarlo?

- Cuando se necesita `append` (agregar datos nuevos sin borrar).

- Cuando se tiene sistemas donde borrar una partición es muy costoso.

- Cuando se no quiere perder datos históricos.

## 🔎 En resumen

`INSERT OVERWRITE` **sirve para sobrescribir una tabla o una partición completa con nuevos datos**, permitiendo cargas limpias, sin duplicados y totalmente idempotentes.

## 🔹 3. Particionamiento por fecha

Cargar particiones completas:

``` sql
DELETE FROM tabla WHERE fecha = '2025-01-01';
INSERT INTO tabla ...
```

## 🔹 4. Deduplicación

Aplicar ventanas:

``` sql
ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC)
```

# 🔹 6. Control de idempotency keys

Común en APIs/eventos para evitar duplicados.

# 🎯 En resumen

**Idempotencia** = Repetir una operación sin causar efectos secundarios.

Es clave para:

- reintentos seguros,

- pipelines confiables,

- evitar duplicados,

- reproducibilidad en ETL/ELT,

- auditoría y consistencia de datos.
