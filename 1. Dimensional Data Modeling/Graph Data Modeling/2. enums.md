# ENUM

En ingeniería de software, un **enum**(abreviatura de ***enumeration*** o ***tipo enumerado***) es un **tipo de dato** que permite definir un conjunto fijo y limitado de valores posibles.

Un enum es como una **lista de opciones válidas y nada más**.

# ¿Para qué sirven los enums?

Sirven para **representar valores constantes** con nombres descriptivos, evitando usar números mágicos o cadenas sueltas que pueden causar errores.

## Beneficios

- **Estandarizan** los valores permitidos.

- **Evitan errores tipográficos** en cadenas.

- **Ordenan y documentan** el código.

- **Hacen el código más mantenible.**

# ¿Cuándo usar enums en ingeniería de datos?

En **pipelines, ETLs o modelos de datos**, los enums son útiles para:

- **Validar dominios**

    - Ej.: estados válidos de un pedido: `new`, `processing`, `fulfilled`.

- **Mantener calidad de datos**

    - Evitar que entre un valor inesperado como `"pendiennte"`.

- **Modelar catálogos pequeños**

    - Ej.: tipo de transacción: `CREDITO`, `DEBITO`.

- **Estandarizar métricas / banderas**

    - Ej.: niveles de severidad: `LOW`, `MEDIUM`, `HIGH`.

# En resumen

Un **enum** es:

- **Un tipo que agrupa un conjunto limitado de valores permitidos, con el objetivo de dar claridad, evitar errores y mejorar la calidad del código y los datos.**

# Los enums son buenos con las subparticiones

Se refiere a que **los enums ayudan a controlar y limitar los valores que se usan como claves de partición o subpartición**, lo cual mejora **performance**, **orden** y **calidad de datos** en sistemas como BigQuery, Snowflake, Hive, etc.

# 1. Qué son las subparticiones

Una partición agrupa datos por un campo grande (ej.: `fecha`).

Una subpartición divide aún más cada partición por otro campo más pequeño (ej.: `tipo_evento`, `país`, `status`).

## Ejemplo:

``` sql 
Partición: fecha = 2025-01-01
    Subpartición: país = MX
    Subpartición: país = GT
    Subpartición: país = SV
```

# 2. Por qué los enums ayudan aquí

Cuando se elige un campo para subparticionar, es fundamental que ese campo tenga:

- **baja cardinalidad** (pocos valores posibles)

- **estabilidad** (los valores no cambian con el tiempo)

- **dominio cerrado** (no aparecen valores nuevos inesperados)

👉 Y justo eso es lo que hace un **enum**:

**Define un conjunto fijo y limitado de valores válidos.**

# Enums en base de datos

En sistemas como BigQuery, si se usa un campo STRING con miles de valores diferentes para subparticionar se:

- cream **muchos directorios internos**

- aumenta **costo de almacenamiento**

- empeora **performance de lectura**

- la tabla se fragmenta

Pero si ese campo es un enum, por ejemplo:

```
Evento: CLICK, VIEW, PURCHASE
TipoUsuario: FREE, PREMIUM
Estado: OK, WARNING, ERROR
```

Entonces:

- la cardinalidad siempre es baja

- las subparticiones siempre son estables

- los queries leen menos archivos

- es fácil planificar y predecir costos

# 4. Ejemplo práctico en BigQuery
❌ **Sin enum (malo para subparticion)**

Campo: `device_model`

Valores: 2,500 modelos distintos.

Subparticionar por esto sería desastroso.

✔ **Con enum (bueno para subparticion)**

Campo: `device_type`

Valores:

- DESKTOP

- MOBILE

- TABLET

Eso funciona perfectamente como subpartición.

# 5. Cómo se usa esto en diseño

Usar enums obliga a que las dimensiones o bronzetables tengan campos discretos y controlados, ideales para:

- `region`

- `event_type`

- `priority`

- `status`

- `source_system`

Todos estos son excelentes subparticiones **porque tienen dominios cerrados.**

# 6. En pocas palabras

- Los enums son buenos para subparticiones porque garantizan que los valores usados para dividir los datos son pocos, predecibles y controlados.
Esto reduce costos, mejora rendimiento y evita fragmentación.
