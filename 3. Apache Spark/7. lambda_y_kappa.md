En **ingeniería de datos**, **Lambda** y **Kappa** son dos patrones de arquitectura para procesar grandes volúmenes de datos, especialmente cuando necesitas ***batch + streaming o tiempo real***.

# 1. Lambda Architecture

La **Lambda Architecture** fue propuesta por **Nathan Marz** (creador de Apache Storm).

## Problema que resuelve

¿Cómo tener:

- Procesamiento en tiempo real

- Procesamiento batch exacto

- Y resultados consistentes

## Estructura

Lambda divide el sistema en **3 capas**

```
                Data Ingestion
                      ↓
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
   Batch Layer    Speed Layer   Serving Layer
```

### 1. Batch Layer

- Guarda **todos los datos históricos**

- Reprocesa todo desde cero

- Produce resultados correctos pero con latencia alta

- Ej: Spark batch jobs

### 2. Speed Layer

- Procesa solo los datos recientes

- Baja latencia

- Resultados aproximados

- Ej: Spark Structured Streaming

### 3. Serving Layer

- Combina resultados de:

- Batch

- Speed

### Ejemplo práctico

Por ejemplo con métricas de ecommerce:

- **Speed layer** → muestra ventas en los últimos 5 minutos

- **Batch layer** → recalcula todo cada noche para corregir errores

- **Serving layer** → junta ambos

### Problema de Lambda

- Doble lógica (batch + streaming)

- Doble mantenimiento

- Mayor complejidad operativa

- Más costos

## Y así nace...

# 2. Kappa Architecture

La **Kappa Architecture** fue propuesta por **Jay Kreps**(cofundador de Apache Kafka).

## Idea principal

- Elimina la capa batch
- Todo es streaming

## Estructura

```
          Data Stream
               ↓
         Stream Processing
               ↓
          Serving Layer
```

Solo una lógica.

## ¿Y si hay que recalcular todo?

En vez de tener batch layer:

- Reprocesas el histórico desde el log

- Ejemplo: desde **Apache Kafka**

- Replay del stream

- Vuelves a calcular todo con el mismo motor streaming

## Lambda vs Kappa

| Característica  | Lambda       | Kappa          |
| --------------- | ------------ | -------------- |
| Capas           | 3            | 1              |
| Batch separado  | Sí           | No             |
| Complejidad     | Alta         | Más simple     |
| Reprocesamiento | Batch layer  | Replay del log |
| Mantenimiento   | Doble código | Código único   |

Actualmente se trabaja:

- Con **Apache Spark** (Structured Streaming)

- Con **Kafka**

- Con motores modernos de streaming

***Mucha gente prefiere Kappa
Porque los motores de streaming ya son suficientemente poderosos para reemplazar batch.***
