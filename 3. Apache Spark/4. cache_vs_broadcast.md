# ¿Qué es Caching?

El cache sirve para:

- Reutilizar un mismo DataFrame varias veces sin volver a recomputarlo.

### Ejemplo:

``` python

    df = spark.read.parquet("ventas").filter("year = 2025")

    df.cache()
    df.count()
    df.groupBy("pais").count()
    df.sum("total")

```

Sin cache:

- Spark recalcula desde el parquet cada vez.

Con cache:

- Se materializa una vez.

- Se guarda en memoria/disco.

- Las siguientes acciones reutilizan el resultado.

**Cache optimiza:**

- **Reutilización dentro del mismo job.**

# ¿Qué es Broadcast?

El broadcast sirve para:

Evitar shuffle en joins cuando una tabla es pequeña.

Ejemplo:

``` python

    df_grande.join(df_pequeno, "id")

```

Normalmente, un `join` implica shuffle:

- Redistribuir datos por red.

- Costoso.

Si `df_pequeno` es pequeño:

Spark:

- Envía la tabla pequeña completa a cada executor.

- Hace el join localmente.

- Evita shuffle masivo.

**Broadcast optimiza:**

- **Joins entre grande + pequeño.**

# Diferencias clave

|                       | Caching                          | Broadcast                  |
| --------------------- | -------------------------------- | -------------------------- |
| Problema que resuelve | Recomputación                    | Shuffle en joins           |
| Qué guarda            | Resultado de un DF               | Copia de una tabla pequeña |
| Dónde se guarda       | BlockManager (RAM/disco)         | Memoria de cada executor   |
| Cuándo se usa         | Reutilizas mismo DF varias veces | Join grande + pequeño      |
| Reduce shuffle        | ❌ No necesariamente              | ✅ Sí                       |
