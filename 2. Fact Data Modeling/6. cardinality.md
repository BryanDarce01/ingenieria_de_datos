# ¿Qué es cardinality?

**Cardinality** = cantidad de valores distintos que tiene una columna.

En SQL sería algo como:

```sql

COUNT(DISTINCT columna)

```

## 1. Low cardinality (baja cardinalidad)

**Pocos valores distintos, aunque tenga millones de filas.**

### Ejemplos claros:

- `gender` → M / F / Other (2–3 valores)

- `status` → active / inactive / pending

- `country` → ~200 países

- `device_type`→ mobile / desktop / tablet

```
device_type
------------
mobile
desktop
mobile
mobile
desktop

```

**Muy pocos valores únicos**

## ¿Dónde se usa mucho?

Dimensiones

Columnas para:

- `GROUP BY`

- `WHERE`

- particiones lógicas

- subparticiones / clustering

## 2. High cardinality (alta cardinalidad)

**Muchísimos valores distintos**, a veces casi uno por fila.

### Ejemplos:

- `user_id`

- `transaction_id`

- `session_id`

- `email`

- `order_id`

- `timestamp` a nivel de milisegundos

```
user_id
-------
U001
U002
U003
U004
...

```

**Casi cada fila es diferente.**

## Relación con fact y dimensional data

**Dimensiones**

- Suelen tener **low cardinality**

Ejemplo:

- país

- categoría

- canal

- estado

**Facts**

- Normalmente **high cardinality**

Ejemplo:

- eventos

- transacciones

- clicks

**Nota**:

- Una dimensión puede ser high cardinality, por ejemplo:

- cliente

- usuario

- producto (si hay millones)

## ¿Por qué importa esto en ingeniería de datos?

**Performance**

- Low cardinality:

    - Más fácil de comprimir

    - Mejores agregaciones

    - Ideal para `GROUP BY`

- High cardinality:

    - `GROUP BY` más caro

    - Más memoria y shuffle

## Particiones / clustering (ej. BigQuery)

❌ Mala idea:

``` sql

PARTITION BY user_id

```

(`user_id` es high cardinality)

✅ Buena idea:

``` sql

PARTITION BY DATE(fecha)
CLUSTER BY country, device_type

```

(low cardinality)

## Regla práctica para decidir

| Tipo de columna | Cardinalidad | Uso recomendado            |
| --------------- | ------------ | -------------------------- |
| gender, status  | Low          | Dimensión, GROUP BY        |
| country         | Low–Medium   | Dimensión, clustering      |
| product_id      | Medium–High  | JOIN, cuidado con GROUP BY |
| user_id         | High         | JOIN, no particionar       |
| event_id        | Muy alta     | Solo identificador         |


## En resumen

**Las columnas de baja cardinalidad son ideales para agrupar y filtrar, mientras que las columnas de alta cardinalidad suelen ser identificadores y no son ideales para particionar ni para hacer agregaciones.**
