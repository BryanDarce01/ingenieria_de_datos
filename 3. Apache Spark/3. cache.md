# Cache

En Spark, `cache()` es un mecanismo para **[materializar](./2.%20elementos_clave/materializar_un_df.md) un DataFrame y reutilizarlo sin volver a recomputarlo.**

Por defecto Spark trabaja así:

- Guarda el logical plan

- Recalcula desde el origen cada vez que ejecutas una acción

``` python 

    df.cache()

```

Significa:
- Cuando este DataFrame se ejecute, guarda sus particiones para reutilizarlas.

⚠️ Importante: `cache()` no ejecuta nada inmediatamente.
Se activa cuando ocurre una acción (`count()`, `show()`, `write()`, etc.).

# 1. Niveles de almacenamiento (Storage Levels)

Spark permite decidir cómo se guardará ese DataFrame usando persist().

Los tres niveles más importantes son:

## 1.1 MEMORY_ONLY

``` python

    df.persist(StorageLevel.MEMORY_ONLY)

```

- Guarda las particiones solo en RAM.

- Si no caben completamente:

    - Las particiones que no entren NO se guardan.

    - Se volverán a recalcular cuando se necesiten.

Ventaja:

- Es el más rápido (leer RAM es más rápido que disco).

Desventaja:

- Puede provocar recomputación si el dataset es grande.

## 1.2 DISK_ONLY

``` python

    df.persist(StorageLevel.DISK_ONLY)

```

- Guarda todo en disco.

- No usa memoria.

- Evita recomputaciones.

- Es más lento que memoria.

Se usa cuando:

- El dataset es muy grande.

- No se quiere consumir RAM.

## 1.3 MEMORY_AND_DISK (el más usado)

``` python 

    df.persist(StorageLevel.MEMORY_AND_DISK)

```

Comportamiento:

1. Intenta guardar las particiones en memoria.

2. Si alguna no cabe:

    - Se escribe automáticamente en disco.

3. No hay recomputación.

Es el nivel más equilibrado y común en producción.

# ¿Qué hace `persist()`?

`cache()` es simplemente un atajo de:

``` python 

    df.persist(StorageLevel.MEMORY_AND_DISK)

```

`persist()` permite elegir el nivel explícitamente.

### Ejemplo:

``` python

    from pyspark import StorageLevel

    df.persist(StorageLevel.MEMORY_ONLY)
    df.count()  # aquí se materializa

```

Sin la acción (`count()`), no se guarda nada.

# ¿Dónde se guarda físicamente?

Los datos se guardan en el `BlockManager` de cada executor:

- Cada partición se almacena en el nodo que la procesó.

- No se centraliza en el driver.

- No es almacenamiento permanente. çç

Si el executor muere → se pierde ese cache.

# ¿Qué pasa si no hago `unpersist()`?

Cuando ya no se va a usar un DataFrame:

``` python 

    df.unpersist()

```

Si no se hace:

- Sigue ocupando memoria

- Puede generar presión de m- emoria

- Puede afectar otros jobs

- En notebooks puede quedarse horas ocupando recursos

Por eso en entornos interactivos siempre se recomienda liberar manualmente.

# Resumen

| Nivel           | RAM | Disco           | Recomputación   |
| --------------- | --- | --------------- | --------------- |
| MEMORY_ONLY     | Sí  | No              | Sí (si no cabe) |
| DISK_ONLY       | No  | Sí              | No              |
| MEMORY_AND_DISK | Sí  | Sí (si no cabe) | No              |

# Idea arquitectónica importante

Cache es:

- Volátil- 

- Solo optimización de performance

- Vive dentro del job

No es:

- Persistencia real

- Sustituto de una tabla staging

- Parte estructural del pipeline

# Regla profesional

Usar- :

- MEMORY_ONLY → cuando sabemos que cabe en RAM y quieremos máxima velocidad.

- MEMORY_AND_DISK → opción segura general.

- DISK_ONLY → cuando el dataset es muy grande y no quieremos presión de memoria.
