En Apache Spark, `sort()` y `sortWithinPartitions()`parecen similares, pero operan en niveles distintos del plan físico y tienen impactos muy diferentes en shuffles, particionamiento y costo computacional.

# 1. `sort()`

En DataFrame API:

``` python

    df.sort("col")
    # o
    df.orderBy("col")

```

## Qué hace realmente

- Realiza un **ordenamiento global**

- Garantiza que el DataFrame completo quede ordenado

- Implica shuffle obligatorio

- Redistribuye los datos entre particiones

## Qué pasa internamente

Spark genera algo conceptualmente así en el plan físico:

``` python

    Exchange (rangepartitioning)
        ↓
    SortExec

```

Paso a paso:

🔁 Exchange (Shuffle)

- Spark redistribuye los datos usando RangePartitioner

- Cada partición recibe un rango de valores de la columna

- Esto implica:

    - Escritura a disco

    - Movimiento de datos entre nodos

    - Network I/O

🔃 Sort dentro de cada partición

- Ahora cada partición ordena sus datos localmente
- Como están particionadas por rango, el resultado es globalmente ordenado

## Resultado

Si tenemos 4 particiones, quedaría así:

```

Partición 1 → valores 0–100
Partición 2 → valores 101–200
Partición 3 → valores 201–300
Partición 4 → valores 301–400

```

Cada partición está ordenada internamente.

Y entre particiones también está ordenado

- Eso es ordenamiento global.

## Coste

`sort()` es una operación **wide transformation** porque:

- Necesita shuffle

- Cambia el esquema de particiones

- Puede ser muy costosa en datasets grandes

# 2. `sortWithinPartitions()`

``` python

    df.sortWithinPartitions("col")

```

## Qué hace realmente

- Ordena **solo dentro de cada partición**

- No hace shuffle

- No cambia el particionamiento

- Es una narrow transformation

## Qué pasa internamente

Plan físico típico:

```

SortExec (local)

```

No hay `Exchange`(shuffle).

Cada executor:

- Toma su partición actual

- Ordena los datos en memoria (o spill si es necesario)

- Devuelve la partición ordenada

## Resultado

Si las particiones estaban así:

```

P1 → [50, 2, 300]
P2 → [10, 900, 4]

```

Con el `sortWithinPartitions`:

```

P1 → [2, 50, 300]
P2 → [4, 10, 900]

```

## Diferencia clave

| Característica           | `sort()` | `sortWithinPartitions()` |
| ------------------------ | -------- | ------------------------ |
| Orden global garantizado | ✅        | ❌                        |
| Shuffle                  | ✅        | ❌                        |
| Cambia particionamiento  | ✅        | ❌                        |
| Wide transformation      | ✅        | ❌                        |
| Costo alto en cluster    | ✅        | Bajo comparado con sort  |


## Cuándo usar cada uno
1. Usar `sort()` cuando:

Se va a hacer:

- `limit()` global

- `window functions` globales

- Exportar archivo final ordenado

- Se cnecesita orden total garantizado

### Ejemplo:

``` python

    df.orderBy("fecha").limit(100)

```

2. Usar `sortWithinPartitions()` cuando:

- Ya se particionó por una key

- Vas a hacer operaciones tipo:

    - Window functions con `partitionBy`

    - Escritura bucketed

    - Optimización para joins sort-merge

- No se necesita orden global

### Ejemplo:

``` python

    df.repartition("user_id") \
    .sortWithinPartitions("timestamp")

```

# Resumen conceptual

``` scss

sort() = orden global + shuffle + caro
sortWithinPartitions() = orden local + sin shuffle + eficiente

```
