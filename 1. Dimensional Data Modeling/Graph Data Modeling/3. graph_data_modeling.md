# graph data modeling

El **graph data modeling** (modelado de datos en grafos) es una forma de diseñar datos pensando en relaciones primero, en lugar de tablas rígidas como en un modelo relacional. 

Se usa principalmente en **bases de datos grafo** como Neo4j, Amazon Neptune, JanusGraph, etc.

# ¿Qué es exactamente?

Es el proceso de representar entidades y sus relaciones usando:

- **Nodos** (**nodes**): representan entidades u objetos (Persona, Producto, Empresa).

- **Aristas (edges/relationships):** representan relaciones entre entidades (AMIGO_DE, COMPRA, TRABAJA_EN).

- **Propiedades (properties)**: atributos tanto de nodos como de relaciones (edad, fecha_compra, rol, etc.).

El enfoque clave es que **las relaciones son “de primera clase”**, no un JOIN secundario como en SQL.

# ¿Para qué sirve?

Se usa cuando lo importante es responder preguntas muy relacionadas con conexiones, por ejemplo:

- ¿Cuál es la ruta más corta entre dos entidades?

- ¿Qué usuarios están más cercanos a un producto o interés?

- ¿Cómo detectar fraudes comparando conexiones entre tarjetas, comercios y transacciones?

- ¿Cuál es la mejor recomendación basada en vecinos en un grafo?

# ¿Cómo se modela?

El proceso típico:

1. **Identificar entidades → nodos**

2. **Identificar relaciones → aristas**

3. **Decidir propiedades necesarias → properties**

4. **Diseñar direccionalidad** (ARISTA A → B)

5. **Definir cardinalidades** (1–N, N–N)

6. **Optimizar para las consultas del grafo**, no para la normalización

## Ejemplo:

| Concepto              | Grafo                        |
| --------------------- | ---------------------------- |
| Persona               | Nodo `(:Person)`               |
| Empresa               | Nodo `(:Company)`              |
| "Trabaja en"          | Relación (:WORKS_AT)         |
| Fecha de contratación | Propiedad dentro de WORKS_AT |

# ¿En qué se diferencia del modelo relacional?

| Relacional (SQL)                                 | Grafo                                      |
| ------------------------------------------------ | ------------------------------------------ |
| JOINs pesados a medida que crecen las relaciones | Relaciones explícitas, traversal rápido    |
| Apto para datos tabulares y transaccionales      | Apto para relaciones complejas y dinámicas |
| Normalización                                    | Desnormalización controlada                |
| Más rígido                                       | Más flexible y evolutivo                   |

# Ejemplo práctico

**Caso: Recomendación de amigos**

Modelo en grafo:

- Nodos: `(:Person)`

- Relación: `(:Person)-[:AMIGO_DE]->(:Person)`

Consulta típica (Neo4j Cypher):

```
MATCH (p:Person)-[:AMIGO_DE]->(f)-[:AMIGO_DE]->(reco)
WHERE p.name = "Juan" AND NOT (p)-[:AMIGO_DE]->(reco)
RETURN reco
```

# ¿Cuándo conviene usar graph data modeling

- Catálogos de productos con relaciones enriquecidas

- Lineage de datos (trazabilidad: qué depende de qué)

- Modelos semánticos o redes de conocimiento

- Sistemas de recomendación

- Análisis de fraude

- Redes sociales

- Sistemas de permisos y roles complejos
