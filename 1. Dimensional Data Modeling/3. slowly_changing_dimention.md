# Slowly Changing Dimension (SCD) o Dimensión de Cambio Lento 

Es un **mecanismo de modelado de datos usado en almacenes de datos** (DWH) para **manejar cómo cambian en el tiempo los atributos de una entidad** (cliente, producto, empleado, etc.), manteniendo o no su historial según el tipo de SCD.

# 🧩 ¿Qué es exactamente una SCD?

Una **dimensión** es una tabla con información descriptiva.

Una **SCD define cómo reaccionamos cuando un atributo de esa dimensión cambia.**

- Ejemplo:
    - Un cliente cambia de dirección, nombre, email, estado civil, etc.

# 🎯 ¿Por qué existen las SCD?

Porque **los valores cambian con el tiempo** y el data warehouse necesita una forma coherente de:

- guardar el estado actual y/o

- conservar el historial de cambios.

Esto permite responder preguntas como:

- “¿Cuál era la dirección del cliente cuando hizo esa compra?”

- “¿Cuántas ventas tuvo un producto mientras tenía tal categoría?”

- “¿Qué cambios tuvo este cliente en los últimos años?”

# 🧱 Tipos principales de SCD

🔵 **SCD Type 0 – Retain Original (sin cambios)**

No se actualiza nada.

La dimensión conserva siempre el valor inicial.

Uso:
Valores que **nunca deben cambiar**(por diseño contractual).

🔵 **SCD Type 1 – Overwrite (sin historial)**

Se actualiza el valor sobrescribiéndolo.

No hay historial.

Ejemplo:

``` sql
UPDATE customer SET email = 'nuevo@mail.com' WHERE id = 1;
```

**Uso**:

- Errores o datos que no requieren historial.

🔵 **SCD Type 2 – Historical Tracking (con historial)**

Cada cambio genera una nueva fila y la antigua se marca como expirada.

Típicamente tiene:

- `surrogate_key`

- `valid_from`

- `valid_to`

- `is_current`

Ejemplo (Spark/dbt/Hive):

| customer_sk | customer_id | name       | valid_from | valid_to   | is_current |
| ----------- | ----------- | ---------- | ---------- | ---------- | ---------- |
| 101         | 1           | Juan       | 2020-01-01 | 2022-03-01 | 0          |
| 158         | 1           | Juan Pérez | 2022-03-01 | 9999-12-31 | 1          |

Uso:

Se necesita **historial completo y precisión temporal**.

🔵 **SCD Type 3 – Limited History (historial limitado)**

Solo mantiene algunos atributos anteriores, típicamente:

- `current_value`

- `previous_value`

Útil cuando el historial completo **no importa**, pero sí 1 versión previa.

🔵 **SCD mixtas o extendidas**:

- **Type 4** → historial en tabla aparte.

- **Type 6** (1+2+3) → combinación de sobrescritura + historial + valores previos.

- **Type 7** → híbrido enterprise temporal + surrogate key.

## 🧠 ¿Dónde se usan las SCD?

En todo DWH/ELT profesional:

- Snowflake

- BigQuery

- Redshift

- Databricks

- SQL Server DW

- Oracle DW

- dbt models (`is_incremental` + `merge`)

## 📌 En resumen

Un **Slowly Changing Dimension (SCD)** es:

**Una técnica para manejar y registrar cambios en los atributos de las dimensiones del Data Warehouse.**

El objetivo es **preservar (o no) el historial** dependiendo del tipo SCD.

## IDEMPOTENCIA CON LAS SCD

| Tipo SCD  | ¿Idempotente por naturaleza? | ¿Idempotente si se implementa bien? | Comentario                                              |
| --------- | ---------------------------- | ----------------------------------- | ------------------------------------------------------- |
| **SCD0**  | ✔️ Sí                        | —                                   | Nunca cambia → idempotencia total                       |
| **SCD1**  | ❌ No siempre                 | ✔️ Sí (con MERGE)                   | Requiere control de cambios                             |
| **SCD2**  | ❌ No                         | ✔️ Sí (con MERGE + HASH)            | Se vuelve idempotente si detectas cambios correctamente |
| **SCD3+** | ❌ No                         | ✔️ Sí                               | Depende de la lógica                                    |
