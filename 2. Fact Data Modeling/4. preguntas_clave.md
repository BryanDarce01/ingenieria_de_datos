# ¿Fact data responde quién, qué, cuándo, dónde y cómo?

- Indirectamente, sí.
- Directamente, responde el “qué pasó” y el “cuánto”

La clave está en que **las preguntas de quién, cuándo, dónde y cómo se responden a través de las dimensiones**, no porque la fact table “explique todo por sí sola”.

## Cómo se ve en un modelo de hechos y dimensiones

## Fact table (fact data)

#### Contiene:

- Eventos o transacciones

- Métricas (medidas)

### Ejemplos:

- ventas

- cantidad

- monto_total

- duración

- clicks

## Responde principalmente:

- s¿Qué pasó?

- ¿Cuánto pasó?

## Dimension tables

Dan el contexto para responder las otras preguntas:

| Pregunta | Dimensión típica           |
| -------- | -------------------------- |
| ¿Quién?  | usuario, cliente, vendedor |
| ¿Qué?    | producto, servicio, acción |
| ¿Cuándo? | tiempo, fecha              |
| ¿Dónde?  | país, ciudad, tienda       |
| ¿Cómo?   | canal, plataforma, método  |

## Relación con los temas vistos antes:

(fact data, dimensiones, normalized vs denormalized)

Esta explicación suele usarse para dejar claro que:

- ❌ **Fact data** ≠ **raw logs**

- ✅ Fact data = **eventos ya modelados**, listos para análisis

- ✅ Diseñada para responder preguntas de negocio

## En resumen

***Las tablas de hechos almacenan las métricas de los procesos de negocio, y las dimensiones proporcionan el quién, qué, cuándo, dónde y cómo.***
