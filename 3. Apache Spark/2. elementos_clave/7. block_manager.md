# BlockManager

El BlockManager es un componente interno de cada executor en Spark.

Es responsable de:

- Guardar particiones cacheadas

- Manejar memoria y disco local

- Coordinar almacenamiento distribuido

Cuando se hace:

``` python

    df.cache()
    df.count()

```

Ocurre esto:

- Cada partición se ejecuta en un executor.

- Esa partición se guarda como un “block”.

- El BlockManager la registra.

Cada partición se almacena como:

``` bash

    blockId → datos serializados/deserializados

```

Y puede estar en:

- RAM

- Disco local

- O ambos

### - Importante

El BlockManager:

- Vive en cada executor

- No está en el driver

- No es almacenamiento global

- No es permanente

Si un executor muere:

- Sus bloques se pierden

- Spark puede recomputarlos usando el [lineage](8.%20lineage.md)

# Como se conecta todo

1. El [Logical Plan](1.%20plan_de_ejecucion.md) describe qué hacer.

2. Cuando se ejecuta (materializa), se genera el Physical Plan.

3. Si se usa [cache/persist](../3.%20cache.md):

    - Los datos materializados se guardan en el BlockManager.

``` powershell

    Código → Logical Plan → Optimizer → Physical Plan → Ejecución → BlockManager (si cacheado)

```

# Resumen

- [Materializar](6.%20materializar_un_df.md) = ejecutar y generar datos reales.

- [Logical Plan](1.%20plan_de_ejecucion.md) = árbol declarativo que describe la consulta.

- BlockManager = sistema distribuido que guarda bloques en memoria/disco.
