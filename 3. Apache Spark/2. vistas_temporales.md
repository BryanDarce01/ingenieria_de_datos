# Una Temporary View en Spark

Es un nombre lógico registrado en el catálogo del `SparkSession` que apunta al ***logical plan*** de un DataFrame.

**IMPORTANTE**

1. No guarda datos.

2. No materializa nada

3. Solo registra cómo construir los datos

***Es básicamente un alias SQL para un DataFrame.***

## 1. Ejemplo

Existe este **df**

 ``` python
 
    df = spark.read.parquet("/data/ventas")
    df = df.filter("year = 2025")

 ```

 Si hacemos:

 ``` python
 
    df.createOrReplaceTempView("ventas_2025")

 ```

Lo que Spark hace es:

- Registrar el nombre `ventas_2025`

- Asociarlo al logical plan del DataFrame

No ejecuta nada todavía (lazy evaluation).

## 2. Qué guarda internamente

Spark trabaja en 3 capas de planificación:

- **Logical Plan**

- **Optimized Logical Plan**

- **Physical Plan**

Cuando se crea una temp view, Spark guarda el **logical plan no ejecutado.**

Algo como esto (simplificado):

``` scss

Project
 └── Filter (year = 2025)
      └── ParquetScan (/data/ventas)

```

Esto es lo que queda asociado al nombre `ventas_2025`.

## 3. Cuándo se ejecuta

Se ejecuta cuando se hace una acción:

``` python

    spark.sql("SELECT COUNT(*) FROM ventas_2025").show()

```

En ese momento:

1. Spark toma el logical plan guardado

2. Lo integra al nuevo query

3. Optimiza todo junto (Catalyst Optimizer)

4. Genera el physical plan

5. Ejecuta el DAG

Si luego se hace otra consulta:

``` python

    spark.sql("SELECT SUM(total) FROM ventas_2025").show()

```

***Se vuelve a reconstruir el plan completo.***

***IMPORTANTE***

**Las vistas temporales son recomputarizadas a menos que se guarden en cache**

## 4. Diferencia con una tabla real

| Temporary View                   | Tabla Persistente                            |
| -------------------------------- | -------------------------------------------- |
| Vive en memoria del SparkSession | Vive en storage (Hive, Delta, Parquet, etc.) |
| No guarda datos                  | Guarda datos físicos                         |
| Se pierde al cerrar sesión       | Permanece                                    |
| Se recalcula cada vez            | No se recalcula                              |

# Tipos de Views en Spark

## 1. Temp View

``` python

    df.createOrReplaceTempView("ventas")

```

- Visible solo en ese SparkSession

- Muere cuando termina la sesión

## 2. Global Temp View

``` python

    df.createOrReplaceGlobalTempView("ventas")

```

- Vive bajo el esquema `global_temp`

- Se consulta así:

``` sql

    SELECT * FROM global_temp.ventas

```

- Dura mientras viva la aplicación Spark

## Para qué sirven realmente

Sirven para:

- Escribir SQL sobre DataFrames

- Mezclar código PySpark/Scala con SQL

- Hacer queries intermedios en notebooks

- Simplificar joins complejos

``` python

    df_clientes.createOrReplaceTempView("clientes")
    df_ventas.createOrReplaceTempView("ventas")

    spark.sql("""
    SELECT c.nombre, SUM(v.total)
    FROM clientes c
    JOIN ventas v ON c.id = v.cliente_id
    GROUP BY c.nombre
    """)

```

## - Qué NO son

No son:

- Una tabla física

- Un mecanismo de persistencia

- Una optimización automática

- Un cache

Son solo una vista lógica temporal.

**TIP**

- Las vistas temporales no mejoran el performance porque no materializan nada.

- Solo registran el logical plan.

En otras palabras:

- Una Temporary View es simplemente una entrada en el catálogo que referencia un logical plan.
