# Lineage en Spark

Es el historial completo de transformaciones necesarias para reconstruir un dataset.

En otras palabras:

- Spark no guarda los datos intermedios por defecto.
Guarda las instrucciones para volver a generarlos.

### Ejemplo:

``` python

    df1 = spark.read.parquet("ventas")
    df2 = df1.filter("year = 2025")
    df3 = df2.groupBy("pais").sum("total")

```

Aquí Spark no ejecuta nada todavía.

Internamente guarda algo como:

``` scss

    ventas (Parquet)
    ↓
    Filter (year = 2025)
    ↓
    GroupBy (pais)
    ↓
    Sum(total)

```

Ese encadenamiento es el **lineage**.

- Es básicamente un DAG (Directed Acyclic Graph) de transformaciones.

# ¿Para qué sirve el lineage?

Sirve principalmente para:

🔥 Fault Tolerance (tolerancia a fallos)

Por ejemplo:

- Un executor se cae

- Se pierde una partición

Spark no necesita tener una copia guardada.

Simplemente:

- Mira el lineage

- Reejecuta solo las transformaciones necesarias

- Reconstruye esa partición

Eso es lo que hace a Spark tolerante a fallos sin replicar todo en memoria.

# Lineage ≠ datos

Muy importante:

El lineage no son los datos.

**Es el plan para reconstruirlos.**

Spark guarda:

- Las dependencias entre RDDs

- Las transformaciones aplicadas

- Cómo regenerar cada partición

# Tipos de dependencias en el lineage

Spark distingue dos tipos:

1.  **Narrow Dependency**

Cada partición depende de una sola partición anterior.

Ejemplo:

- filter

- map

- select

No requiere shuffle.

2.  **Wide Dependency**

Una partición depende de múltiples particiones anteriores.

Ejemplo:

- groupBy

- join

- reduceByKey

Requiere shuffle.

Las wide dependencies generan nuevas etapas (stages) en el DAG.

# ¿Qué pasa cuando el lineage es muy largo?

Si el Dataframe tiene muchas transformaciones:

``` python 

    df = df.filter(...).join(...).groupBy(...).withColumn(...)

```

El lineage crece.

Problemas posibles:

- Planes muy grandes

- Mayor costo de recomputación

- Más memoria en el driver

Por eso a veces se usa:

- cache()

- persist()

- write (staging)

Para "cortar" el costo práctico del lineage.


# ¿Cache rompe el lineage?

No.

Aunque se materialice con cache:

- El lineage sigue existiendo.

- Spark lo mantiene por si necesita recomputar.

Lo que cache hace es:

- **Guardar una copia para no recorrer todo el lineage cada vez.**

# Visualmente

Sin cache:

``` sql

    Parquet → Filter → Join → GroupBy → Action

```

Si falla una partición en GroupBy:

Spark mira el lineage y vuelve a ejecutar desde Parquet hasta GroupBy solo para esa partición.

# Por eso

**Lineage is the logical dependency graph that Spark uses to recompute lost partitions instead of replicating data.**

Es el mecanismo central de fault tolerance en Spark

# Resumen

Lineage = historial de cómo construir el dataset.

Permite recomputar particiones perdidas.

Es un DAG de transformaciones.

No son datos, son instrucciones.
