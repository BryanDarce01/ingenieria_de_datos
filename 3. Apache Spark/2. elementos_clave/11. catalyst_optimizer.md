# Catalyst Optimizer

**Catalyst** es el motor de optimización de consultas SQL y DataFrames en Spark.

Es el componente que toma el código declarativo (SQL o DataFrame API) y lo transforma en un plan de ejecución eficiente.

# 1. Por qué existe Catalyst

Cuando escribimos:

``` python

    df.filter("year = 2025").select("id", "total")

```

Eso es declarativo.
Estamos diciendo **qué queremos**, no **cómo hacerlo**.

El Catalyst decide:

- Qué filtros aplicar primero

- Qué columnas realmente leer

- Qué estrategia de join usar

- Cómo ordenar el plan de ejecución

- Cómo generar código optimizado

# 2. Las 4 fases de Catalyst

Cuando ejecutas una consulta, pasa por 4 etapas:

## 2.1. Parsing

Convierte el SQL o DataFrame API en un árbol lógico.

Ejemplo SQL:

``` sql

    SELECT id, total FROM ventas WHERE year = 2025

```

Se convierte en un [Logical Plan](1.%20plan_de_ejecucion.md):

``` scss

Project [id, total]
 └── Filter (year = 2025)
      └── Relation (ventas)

```

## 2.2. Analysis

- Verifica que las columnas existan

- Resuelve tipos de datos

- Valida tablas

- Resuelve aliases

Convierte el plan en un Analyzed Logical Plan.

## 2.3. Optimization

Aquí ocurre la magia.

Catalyst aplica reglas como:

- Predicate Pushdown

- Column Pruning

- Constant Folding

- Join Reordering

- Simplificación de expresiones

Ejemplo:

``` sql

    df.select("id", "total").filter("year = 2025")

```

Catalyst puede reordenarlo a:

``` css

Filter → Project

```

Este resultado es el **Optimized Logical Plan.**

## 2.4. Physical Planning

Aquí decide:

- ¿Hash join o sort-merge join?

- ¿Broadcast join?

- ¿Cuántas particiones?

- Cómo dividir en stages?

Produce el Physical Plan, que ya se ejecuta sobre [RDDs](9.%- 20rdd.md).

# 3. Whole-Stage Code Generation

Catalyst no solo optimiza el plan.

También genera código Java optimizado dinámicamente.

En lugar de ejecutar operación por operación, genera código compilado que:

- Reduce overhead

- Minimiza llamadas de función

- Mejora uso de CPU

Eso es parte del motor Tungsten.

### Ejemplo

``` python

    df.explain(True)

```

Se verá:

- Parsed Logical Plan

- Analyzed Logical Plan

- Optimized Logical Plan

- Physical Plan

Eso es Catalyst trabajando.

# 4. Por qué Catalyst es importante

Gracias a Catalyst:

- DataFrames son mucho más rápidos que RDDs.

- SQL en Spark es altamente optimizado.

- No nos preocupamos por el orden exacto de transformaciones.

Spark puede cambiar estrategias dinámicamente.

# Resumen

Catalyst es:

- ***Un optimizer basado en árboles que transforma planes lógicos en planes físicos optimizados mediante reglas y generación de código.***

Es el cerebro que convierte el código declarativo en ejecución eficiente.
