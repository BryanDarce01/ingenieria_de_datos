# Shuffle

El shuffle es uno de los procesos más costosos en Spark.

Definición técnica:

- Shuffle es el proceso de redistribuir datos entre particiones para agruparlos por clave.

## ¿Cuándo ocurre shuffle?

Cuando hacemos operaciones que requieren reorganizar datos globalmente:

- groupBy

- join

- reduceByKey

- distinct

- orderBy

## Ejemplo

Tenemos los datos por país distribuidos así:

``` yaml

Partición 1: GT, MX, GT
Partición 2: MX, US
Partición 3: GT, US

```

Si hacemos:

``` python

    df.groupBy("pais").count()

```

Spark necesita que todos los "GT" estén juntos, todos los "MX" juntos, etc.

Entonces ocurre:

- Se re-hashea la clave (pais)

- Se envían datos por red

- Se redistribuyen entre nodos

- Se agrupan

Eso es el shuffle.

Qué implica el shuffle

Shuffle implica:

- Movimiento de datos por red

- Escritura a disco temporal

- Creación de nuevas particiones

- Nueva etapa (stage) en el DAG

Por eso es costoso.

# Narrow vs Wide Dependencies

Esto conecta con [lineage](8.%20lineage.md).

- Narrow dependency (sin shuffle)

``` css

    map
    filter
    select

```

Cada partición depende de solo una partición anterior.

No hay movimiento de red.

- Wide dependency (con shuffle)

``` sql

    groupBy
    join
    distinct

```

- Una partición depende de múltiples particiones anteriores.

- Hay redistribución.

- Eso crea un nuevo stage en el DAG.

## Ejemplo visual

Sin shuffle:

``` mathematica

Parquet → Filter → Map → Count

```

Con shuffle:

``` mathematica

Parquet → Filter → Shuffle → GroupBy → Count

```

El shuffle divide el job en múltiples stages.

# Por qué el shuffle es tan importante

Porque:

- Consume red

- Consume disco

- Consume CPU

- Puede causar skew

- Puede generar OOM

Muchos problemas de performance en Spark son problemas de shuffle.
