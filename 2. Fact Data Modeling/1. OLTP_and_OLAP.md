# OLTP y OLAP 

Describen para qué tipo de **trabajo está diseñada una base de datos.**

# OLTP (Online Transaction Processing)

Está diseñado para operaciones transaccionales del día a día.

# ¿Para qué sirve?

- Registrar eventos en tiempo real.

- Sistemas operativos: apps, APIs, sistemas internos.

- Muchas operaciones pequeñas y rápidas.

# Características

- Muchísimas operaciones ``INSERT`` / ``UPDATE`` / ``DELETE``.

- Consultas simples por **PK**.

- Datos **normalizados**.

- Alta concurrencia (muchos usuarios al mismo tiempo).

- Transacciones ACID.

# Ejemplos típicos

- Sistema bancario

- E-commerce (pedidos, pagos)

- CRM

- ERP

# OLAP (Online Analytical Processing)

Está diseñado para **análisis de datos y toma de decisiones**.

# ¿Para qué sirve?

- Reportes

- Dashboards

- Análisis histórico

- KPI´s

# Características

-   - Lecturas pesadas sobre millones o billones de filas.

- Queries complejos:

    - ``GROUP BY``

    - ``SUM``

    - ``AVG``

    - ``JOIN``

- Datos **denormalizados**.

- Menos escrituras, pero en **bloques grandes** (batch).

# Ejemplos típicos

- Data Warehouse

- BigQuery

- Snowflake

- Redshift

- ClickHouse

OLTP vs OLAP

| Característica   | OLTP             | OLAP               |
| ---------------- | ---------------- | ------------------ |
| Tipo de uso      | Operacional      | Analítico          |
| Escrituras       | Muchas, pequeñas | Pocas, grandes     |
| Lecturas         | Simples          | Complejas          |
| Volumen de datos | Bajo / medio     | Muy alto           |
| Modelo           | Normalizado      | Denormalizado      |
| Latencia         | Milisegundos     | Segundos / minutos |
| Usuarios         | Apps / usuarios  | Analistas / BI     |

# Regla fácil de recordar

- **OLTP = “guardar”**

- **OLAP = “analizar”**
